tokenlive-gateway 架构图

Gin 外壳 + Engine Pipeline + ClusterInvoker 编排 · OpenAI 兼容的多上游高性能 LLM API 网关

请求处理链路

  • • Gin 薄外壳直通 Engine.HandleRequest，/v1（Chat · Responses · Messages · Embeddings）+ /v1beta（Gemini 原生）
  • • Inbound / Outbound 每请求各执行一次，重试只发生在 Invoker 内部
  • • 全链路 SSE 解析与拦截，精确记录 TTFT 与 Token 用量
  • • Inbound 拒绝时仅执行 InboundSafe 的 Outbound 过滤器

治理与可靠性

  • • 策略按 租户 / 用户 / 模型 维度解析下发，运行时可切换 Invoker 与动态 Fallback
  • • Router 纯过滤链：能力 / 熔断 / 优先级 / 标签 / 租户端点，叠加 10 种负载均衡
  • • 服务级 + 实例级双熔断，半开探测许可，慢调用（TTFT/RTT）计为失败
  • • 跨模型 Fallback + Hedging；流式首包发出后不再重试，避免污染响应

数据与运维

  • • Redis StateStore（无 Redis 自动降级内存）+ 补偿队列 Worker 兜底
  • • 访问日志异步批量入 ClickHouse；业务事件发布 Kafka / Redis / HTTP
  • • 配置多源热更新：YAML / Redis / HTTP 轮询 / 嵌入式 Provider
  • • Prometheus 指标 + Zap 日志 + OTel 链路三件套
