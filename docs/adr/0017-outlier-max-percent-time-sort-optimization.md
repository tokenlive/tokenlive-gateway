# 0017. 实例级熔断最大比例（OutlierMaxPercent）超限时引入按熔断打开时间排序的放通机制

## 状态

已接受 (Accepted)

## 上下文

在 tokenlive-gateway 系统的实例级（Endpoint 级）熔断治理中，通过 `OutlierMaxPercent` 配置了最大允许熔断的实例比例（例如 $20\%$），以防在大面积网络抖动或上游故障时，所有端点全量熔断导致整个模型服务完全不可用。

此前，当熔断的实例数量超过最大允许熔断限制（`maxAllowed`）时，网关会对所有被熔断的实例列表（`groupBlocked`）按 **ID 字典序升序** 排序，仅保留前 `maxAllowed` 个端点继续熔断，其余端点被强行“放通”尝试路由。

静态的 ID 字典序排序存在以下弊端：

- **静态偏向导致负载极度失衡**：固定 ID 大小决定了哪些端点被保留熔断、哪些被强行放通。ID 较小的端点将永久被屏蔽，而 ID 较大的损坏端点在超限时总是会被强行放通，这会导致路由极度失衡，局部可用性大打折扣。
- **缺乏运行时自适应性**：无法区分“硬故障（挂了很久的节点）”与“软抖动（刚刚遭遇瞬时故障的节点）”，错误地将流量路由至已知长期宕机的实例。

## 决策

为了提高大面积故障情况下的系统自适应路由与容灾成功率，我们进行了如下重构与优化决策：

1. **引入基于熔断打开时间的排序机制**：
   - 提取每个处于 Open/Half-Open 状态的熔断器的状态变迁时间（`openSince`）。
   - 当熔断数量超限时，将 `groupBlocked` 列表**按熔断打开时间升序排序**（`openSince` 更早、即熔断越久的排在前面）。
   - 保留前 `maxAllowed` 个最早熔断的节点继续处于屏蔽状态（因为它们很有可能是硬故障，或完全不可用）；其余后熔断（最近刚熔断，可能只是瞬时抖动，具备抢救可能性）的实例则超出阈值被强行放通。

2. **多重排序字段兜底 (Deterministic Sort)**：
   - 在排序比较中，如果两个实例的熔断时间完全相同（例如在并发瞬时调用下被同时熔断，或者在单元测试中同批次熔断），则降级使用 `ID 字典序` 作为二级排序条件，以保障排序结果的绝对确定性。

3. **暴露时间查询接口**：
   - 在 `CircuitBreakerManager` 中增加并暴露了 `GetOpenSince(key string) time.Time` 接口。
   - 内部利用 RLock 保护 entries 读取，并在获取具体 `entry` 时使用互斥锁读取 `state` 和 `openSince` 字段，以保证在多协程高并发请求下的并发安全与 Data Race 零风险。

## 后果

- **提高容灾成功率**：避免了静态 ID 的路由失衡，高并发下能够自适应地将超限放通的流量导向最近刚挂的、更有存活机会的实例。
- **逻辑自洽与透明性**：当状态机在冷却到期步入 `Half-Open` 探活时，其 `openSince` 时间保持不变（继承原熔断时间点），保证了时间比对跨状态周期的连续性。
- **测试可靠性**：我们追加了针对时间升序排序和 ID 二级排序的完整单元测试，验证了排序与放通策略符合预期。
