# ADR 0020: 亲和性策略下的原地重试与降级保护

## Status

Accepted

## Context

在 LLM 网关中，**端点亲和性（Endpoint Affinity / 会话粘性）**主要是为了最大化命中上游物理节点的 **Prompt Cache（提示词缓存）**，从而降低首字延迟（TTFT）并降低 Token 计费。

然而，在默认的位置故障转移（Failover）重试逻辑下，网关会对失败节点进行“单次请求内的临时排除”（即加入 `excluded` 列表，重试时漂移到其他端点）。这产生了两个冲突：

1. **缓存失效**：临时排除会导致带有亲和性的请求漂移到不具缓存的异构物理端点上，造成 TTFT 暴增与计费增加。而在某些瞬时抖动（如偶然连接中断）或 429 限流下，原地退避重试才是保留 Cache 的最佳解。
2. **异构模型污染**：如果当前 Model 所有的物理端点都耗尽或排除，且配置了 `Fallback Chain`，系统会自动尝试“策略降级（跨 Model 降级）”以保障可用性。但对于开启了端点亲和性且需要锁定模型输出风格的请求，自动跨 Model 降级会破坏其输出的一致性，带来业务逻辑的混乱。

## Decision

1. **支持显式配置排除失败端点（`exclude_failed_endpoint`）**：
   - 摒弃将“原地重试”硬编码为单一模式（如 `RetrySame`）的做法，而是通过在重试策略中引入布尔参数 `exclude_failed_endpoint` (默认值为 `true`) 来灵活控制。
   - **当设为 `true`（默认）**：发生重试时，会将先前失败的端点加入临时排除列表，从而触发故障转移（Failover）至其他端点。
   - **当设为 `false`**：发生重试时不排除失败端点，保留在此物理端点上继续请求。原地重试要求重试必须采用指数退避（Exponential Backoff with Jitter）以防产生重试风暴压垮上游。
2. **端点亲和性防策略降级（Affinity Protection）**：
   - 当端点亲和性（Endpoint Affinity）策略开启且用户选择不发生降级时，网关应当在重试机制中**屏蔽策略降级（跨 Model Fallback 降级）**。
   - 若主模型的所有候选端点在重试后均不可用，系统直接向客户端抛出底层错误，严禁自动调用 fallback 链漂移到下一个降级模型，以此保护亲和会话的一致性。
3. **熔断状态判定优先于重试（Circuit Breaker Priority）**：
   - 熔断器作为高可用的核心自我保护机制，具有最高优先级。
   - 在 `exclude_failed_endpoint = false` (原地重试) 的重试流转中，每次发起下一次 Attempt 前必须校验该端点的熔断器状态。如果端点已在第一次失败后被熔断器判定为 `Open`（熔断开启），则必须立刻阻断原地重试流，直接向客户端返回熔断降级或 503 异常，不得强行在该故障端点上“带病重试”。

## Consequences

**正面：**
- 极大提升了对 Prompt Cache 的保护能力，在发生网络瞬抖或 429 时，能够通过设置 `exclude_failed_endpoint = false` 原地退避最大概率保住缓存。
- 确保了亲和会话在遭遇故障时不会被自动降级机制“悄悄”路由到其他异构模型上，保护了模型输出风格、采样行为和能力的一致性。
- 通过引入指数退避，保护了原地重试时的上游负载。
- 明确了熔断器的最高防线地位，防止原地重试退化成灾难性的重试风暴和故障堆积。

**负面：**
- **可用性让步**：当 `exclude_failed_endpoint = false` 时，若物理端点发生了持续性的彻底宕机，原地重试无法自动 Failover 漂移到其他存活端点，这会导致该请求在尝试完重试次数前（或触发熔断前）一直停留在该节点，高可用表现略有下降。
- 配置复杂度上升，用户需要更加清楚地认知业务在可用性（Availability）和一致性/缓存（Affinity/Cache）之间的比重并做配置。

## Alternatives considered

- **基于错误类型智能决定**：宕机类强制漂移，限流/网络瞬抖原地退避。被否，因为对 429 或 5xx 的分类判定依赖于各个大模型厂商返回的格式（有些 429 属于偶发超配额而非物理故障），在网关侧较难做到 100% 绝对的智能分类判定，由用户显式进行配置更能控制生产确定性。
- **混合重试（前 N 次原地重试，后 M 次漂移重试）**：过于复杂，引入过多的策略复杂度，对性能提升有限。
