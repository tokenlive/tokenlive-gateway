tokenlive-gateway Architecture

Gin shell + Engine pipeline + ClusterInvoker orchestration · A high-performance, OpenAI-compatible, multi-upstream LLM API gateway

Request Pipeline

  • • A thin Gin shell forwards to Engine.HandleRequest; /v1 (Chat · Responses · Messages · Embeddings) + /v1beta (native Gemini)
  • • Inbound / Outbound filters run exactly once per request; retries happen only inside the Invoker
  • • Full-path SSE parsing and interception for precise TTFT and token accounting
  • • On Inbound rejection, only InboundSafe Outbound filters execute

Governance & Reliability

  • • Policies resolved per tenant / user / model; runtime invoker switching and dynamic fallback
  • • Pure filter Router chain: capability / circuit breaker / priority / tag / tenant endpoint, plus 10 LB strategies
  • • Dual-level (service + instance) circuit breakers, half-open permits, slow calls (TTFT/RTT) count as failures
  • • Cross-model fallback + hedging; no retry once the first stream byte is sent

Data & Operations

  • • Redis StateStore (auto-degrades to in-memory) + compensation queue worker as backstop
  • • Access logs batched asynchronously into ClickHouse; business events published to Kafka / Redis / HTTP
  • • Multi-source config hot reload: YAML / Redis / HTTP poller / embedded provider
  • • Prometheus metrics + Zap logs + OpenTelemetry tracing
